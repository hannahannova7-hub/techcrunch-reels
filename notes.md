# Заметки к гайду — первый пробный прогон (14.10.2026)

## Что сделано по шагам

1. **Прочитаны правила стиля.** Это три файла из папки «Сценарии видео»: стиль сценариев, правки Ани и выгрузка из Notion. Из выгрузки взяты два эталонных новостных сценария, про Meta Muse и про звонок из Google. Доступ к папке был, отдельно запрашивать его не пришлось.
2. **Получен список свежих новостей.** Вместо поиска открыт RSS-адрес TechCrunch `techcrunch.com/feed/`. Это служебная страница сайта со списком последних 20 статей, у каждой есть дата и рубрика. Так быстрее и надёжнее поиска.
3. **Выбраны три кандидата, оставлен один** (см. result.md). Остальные отсеяны по правилам: политика, только обвинение, только цифра.
4. **Проверены факты.** Открыты первоисточники: блог YouTube, справка YouTube, пресс-релизы Deezer. Дальше найдены независимые издания: Engadget, Music Week, TechCrunch. Каждый факт сверялся в трёх местах. То, что нашлось в одном месте, вычеркнуто.
5. **Написан сценарий**, сохранён в result.md.

## Ошибки и исправления

- **Первый вариант сценария вышел длинным: 348 слов, примерно 2,5 минуты.** Пришлось сократить до 215 слов. Вывод: нужно заранее задавать лимит слов, для 60–90 секунд это примерно 150–220 слов.
- **Обычный веб-поиск не находил сегодняшние новости.** Индекс поисковика отстаёт на несколько часов. Помог более глубокий режим поиска и прямой переход на сайты компаний.
- **Один сайт, Music Business Worldwide, не открылся (ошибка 403).** Он не пускает автоматических читателей. Его вывод учтён только как оговорка, он не считался подтверждением.
- **Чуть не прошла аналогия «примерно как в Spotify».** Убрана, потому что по правилам Ани аналогий нет.

## Что было непонятно

- **Разговорный темп Ани не измерен**, поэтому длительность пока оценочная. Самый простой способ узнать темп: записать любой готовый сценарий и разделить число слов на число минут.
- В эталонах из Notion текст разбит на блоки с заголовками, а в файле правок сказано, что заголовков внутри речи быть не должно. В этот раз текст идёт сплошным потоком без заголовков. Стоит решить, как правильно.

## Как проверить результат

- Число слов посчитано командой, без оценки на глаз.
- Каждая ссылка в result.md действительно открывалась во время работы. Исключения помечены отдельно: у MBW ошибка 403, а DJ Mag известен только по поисковой выдаче.
- Прочитать сценарий вслух с секундомером.

## Время и расходы

Точных данных нет, поэтому не фиксируются.

## Что Ане понадобится понять, чтобы объяснить это новичку

- **Что такое RSS-лента** и почему список новостей лучше брать из неё, а не через поиск.
- **Первоисточник и перепечатка**: почему пять статей, пересказывающих один пресс-релиз, это всё равно один источник.
- **Почему ИИ пишет длиннее, чем нужно**, и как сразу задать лимит слов.
- **Почему ИИ иногда не может открыть сайт** (403, защита от ботов) и что делать в таком случае.
- **Где лежат правила стиля**: модель пишет «в твоём стиле» только потому, что перед работой прочитала файлы с правилами. Без них стиля не будет.

# Этап 4 — данные не пропадают после перезапуска (15.10.2026)

## Решение

Вместо Railway с Postgres выбрана база SQLite в одном файле рядом с ботом (`news.db`). Почему: Railway платный, регистрацию в нём человек проходит сам, а у бота пока нет данных, которые нужно держать на сервере. Задание прямо разрешает такой вариант для программ, которые работают на компьютере.

## Что сделано

1. Добавлен `storage.py`: таблица `sent_news` хранит ссылку, заголовок, дату публикации, время первой отправки и сколько раз новость присылалась.
2. `/news` теперь помечает новости: 🆕 — новая, ↩️ — уже присылалась.
3. Добавлена команда `/history`.
4. База сначала проверена на временном файле, без Telegram: при первом вызове 7 новых новостей, при втором 0 новых и 7 повторов.
5. Проверка перезапуском: `/news` и `/history`, скриншот «до» → бот полностью остановлен, процесса больше нет, а файл `news.db` остался на диске → бот запущен заново → `/history`, скриншот «после».

## Что понадобится объяснить новичку

- Чем «в памяти» отличается от «в базе»: память программы очищается, когда программа закрывается, а файл на диске остаётся.
- Что такое SQLite: база данных в одном файле, без сервера и без установки.
- Когда пора переходить на Postgres в облаке (Railway): когда программа должна работать круглосуточно без вашего компьютера.

# Этап 5 — задачи агенту из Telegram (16.10.2026)

## Что сделано

1. Терминальная версия Claude Code залогинена через `claude auth login`: подтверждение в браузере, код вставлен в отдельное окно.
2. Бот принимает задачи от владельца (`TELEGRAM_OWNER` в `.env`): любое сообщение без «/» превращается в задачу. Бот отвечает «Принято, работаю…», выполняет её через `claude -p` в папке проекта и присылает результат.
3. Задачи выполняются строго по очереди, по одной, и хранятся в `news.db` (таблица `tasks`).
4. Задачи, пришедшие пока бот был выключен (Telegram хранит их около суток), сами не выполняются: бот присылает список и ждёт `/run` или `/skip`.
5. Claude из бота может только читать, искать в интернете, писать файлы проекта и запускать `py fetch_news.py`.

## Ошибки и исправления

- `auth login` в фоне сразу получил пустой код и завершился. Правильно открыть отдельное окно, куда человек сам вставит код.
- Разрешение `Bash(py fetch_news.py)` не сработало: на Windows Claude запускает команды через PowerShell. Добавлено `PowerShell(py fetch_news.py)`.
